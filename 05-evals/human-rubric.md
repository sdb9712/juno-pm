# Human Evaluation Rubric · Juno

_Module 5. Generated by `M5 - Human Evaluation Rubric.html`. Paste over `05-evals/human-rubric.md`._

## What graders score

- **What you’re scoring:** Risk Flagging and task Prioritization
- **Value proposition:** Turn every inquiry from Slack, email, Notion, Jira and CRM call notes into one task per problem (merging similar inquiries into the same task), prioritize each by business impact (R × S × B), and make it ready to build, with linked sources and a score explanation I can check.

## Dimensions

| Dimension | Question | Scale | 1 or No | 3 | 5 or Yes |
|---|---|---|---|---|---|
| Source Accuracy (deal-breaker) | Does every linked source exist and match what the task says about it? | Yes / No | At least one link is missing or broken, points to something that doesn’t exist, or names the wrong client | n/a | Every link opens a real Slack message, email, Jira ticket, Notion page or CRM call note, and the client named in the task matches the client in the source. |
| Score Presence | Does this task have a priority score with an explanation, or a PM Review status with a reason? | Yes / No | The task is missing the score, the level or the explanation, and is not in PM Review. | n/a | The task shows an R × S × B score, a level (Fix now / Plan next / Backlog) and a written explanation of the score, or it is in PM Review with the reason shown. |
| Score Accuracy | Does this task’s R × S × B score match the sources and CRM data? | 1 to 5 | Two or more factors (R, S, B) are wrong, or the override rule (S = 4 and B ≥ 4 → Fix now) was missed, so the task sits at the wrong level. | One factor is off by one point, but the task still lands at the correct level (Fix now / Plan next / Backlog). | R matches the number of unique clients, S matches the described impact, B matches the clients’ total ARR plus churn signals, and the level is correct |
| Task Description Completeness | Does this task’s description cover everything the linked sources report about the problem? | 1 to 5 | The description misses the main problem from the sources or describes a different problem. A developer could not start work without reading the sources. | The main problem is described, but at least one detail from the sources is missing (affected clients, steps to reproduce, or expected behavior). A developer would need to ask the PM a question. | Every problem and detail reported in the linked sources is in the description. A developer could start work without opening the sources. |
| Signal Grouping (deal-breaker) | Are all linked signals about the same problem, and is no other open task about this same problem? | Yes / No | At least one linked signal describes a different problem, or another open task in the dashboard covers the same problem (a duplicate). | n/a | Every linked signal describes the same problem, and the dashboard has no other open task for it.  |

## Calibration

- **How many answers you’ll score, and how often:** 10 tasks per week
- **Who scores them with you:** Me, plus head of support
- **What happens when two of you disagree:** If our scores differ by 2 or more on any question, we talk it through and rewrite that description so it’s clearer next time.

## Pass bar

A minimum 4 on questions 3 and 4 and every yes or no question passes

**Fails outright, whatever the average:**

- Source Accuracy: any "no"
- Signal Grouping: any "no"
